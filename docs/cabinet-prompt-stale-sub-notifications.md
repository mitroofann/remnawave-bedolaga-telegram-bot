# Промпт для Опуса, работающего над кабинетом (фронт)

Скопируй текст ниже в соседнее окно.

---

В админке `/admin/settings` нужно разместить группу новых настроек для фичи
**«Уведомления о несвежей подписке»**. Бэкенд (Web API бота) уже готов — настройки
автогенерируются из pydantic-модели, со стороны фронта нужно только отображение в
разделе «Уведомления пользователям».

## Контекст фичи

Раз в сутки бот проверяет активных пользователей: если какое-то устройство было
подключено к VPN недавно, но **давно не запрашивало актуальный список серверов**
(подписка «застыла» — приложение сломалось), пользователю отправляется уведомление
с советом обновить подписку вручную и рекомендацией приложений Happ/INCY.

Управляется шестью настройками с префиксом `NOTIFY_STALE_SUB_*`.

## Что уже есть на бэкенде

Настройки уже попадают в API `/admin/settings` и уже сгруппированы в категорию
**«🔔 Уведомления пользователям»** (`NOTIFICATIONS`). Каждая — обычный key-value
параметр (как остальные настройки бота). Никакой новой логики добавлять не нужно.

Типы и значения по умолчанию:

| Ключ | Тип | Дефолт | Смысл |
|---|---|---|---|
| `NOTIFY_STALE_SUB_ENABLED` | boolean (тумблер) | `false` | Включает суточную проверку «несвежих» подписок |
| `NOTIFY_STALE_SUB_CHECK_TIME` | string `HH:MM` | `12:00` | Время суточной проверки (UTC) |
| `NOTIFY_STALE_SUB_LAST_SEEN_HOURS` | number (целое) | `24` | Устройство было онлайн недавно (часы) |
| `NOTIFY_STALE_SUB_LAST_REQUEST_HOURS` | number (целое) | `72` | Подписка не обновлялась давно (часы) |
| `NOTIFY_STALE_SUB_COOLDOWN_DAYS` | number (целое) | `5` | Как долго не слать повторное уведомление (дни) |
| `NOTIFY_STALE_SUB_RECOMMEND_APPS` | boolean (тумблер) | `true` | Добавлять рекомендацию Happ/INCY |

## Что сделать на фронте

1. В `/admin/settings` в разделе **«🔔 Уведомления пользователям»** отобразить эти 6
   настроек (они уже приходят в общем списке настроек категории — просто убедиться, что
   они рендерятся как обычные параметры: тумблер для boolean, число для number, текст
   для `HH:MM`).
2. Если в проекте есть отдельные группы «продвинутых» настроек — эти попадают в ту же
   категорию, что и `ENABLE_NOTIFICATIONS` / `NOTIFICATION_CACHE_HOURS` (рядом с ними).
3. Подсказки (description/format/example) уже приходят с бэкенда — отображать их как у
   остальных настроек категории.
4. Для `NOTIFY_STALE_SUB_CHECK_TIME` формат ввода — `HH:MM` (строка, без валидации часового
   пояса: бот хранит время в UTC и так показывает).

## Подсказка для пользователя (текст рядом с блоком)

Что-то вроде: «Раз в сутки бот проверяет, есть ли у пользователей устройства, которые
активно используются, но давно не запрашивали список серверов (подписка "застыла").
Таким пользователям отправляется уведомление с советом обновить подписку вручную и
рекомендацией приложений Happ/INCY. Повторные уведомления не отправляются чаще, чем раз
в COOLDOWN_DAYS дней.»

## Не делать

- Не добавлять никакой новой логики и вызовов к RemnaWave — только отображение настроек.
- Не менять значения по умолчанию и не переносить эти настройки в другие категории.
- Не трогать остальные настройки категории «Уведомления пользователям».
