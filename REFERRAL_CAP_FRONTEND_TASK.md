# Задача для фронтенда: лимит реферальной комиссии

## Контекст

В бэкенде добавлена новая настройка реферальной программы (legacy-схема):

- **Ключ**: `REFERRAL_MAX_COMMISSION_KOPEKS`
- **Тип**: integer (копейки)
- **Значение по умолчанию**: `0` — лимит выключен
- **Смысл**: потолок **разовой** процентной комиссии реферера (пригласившего) **с одного пополнения** реферала. Процент считается как раньше (`сумма × процент`), но если результат превышает этот потолок — выплачивается только потолок. Пример: комиссия 25%, пополнение 10 000 ₽ → «сырая» комиссия 2 500 ₽; при потолке 500 ₽ (50000 копеек) реферер получит 500 ₽.
- **Что НЕ ограничивает**: фиксированные бонусы (`REFERRAL_INVITER_BONUS_KOPEKS`, бонус за первое пополнение реферала) — они выплачиваются как раньше. Лимит применяется только к процентной части, и отдельно к каждому пополнению (не к сумме за период).
- **Действует только в legacy-схеме** (`REFERRAL_REWARD_SCHEME='legacy'`). В многоуровневой схеме (`levels`) настройка игнорируется — учтите это в подсказке в UI.

Настройка **автоматически зарегистрирована** в системе настроек: она доступна через общий API настроек — `GET /cabinet/admin/settings` (в категории `REFERRAL`, заголовок «Реферальная программа») и `PUT /cabinet/admin/settings/{key}`. Отдельный эндпоинт для неё создавать не нужно.

Копейки — это внутреннее представление. В UI показывать и вводить **рубли**, в API отправлять копейки (умножение/деление на 100).

## Что нужно сделать

В админке в разделе настроек реферальной программы (там, где уже есть `REFERRAL_COMMISSION_PERCENT`, `REFERRAL_INVITER_BONUS_KOPEKS` и т.п.) добавить одно поле:

### Поле «Максимальная комиссия с одного пополнения»

- **Расположение**: рядом с полем процента комиссии (`REFERRAL_COMMISSION_PERCENT`) — это связанная настройка.
- **Label**: «Максимальная комиссия с одного пополнения, ₽»
- **Ввод**: неотрицательное число с возможностью дробной части (до 2 знаков). Пустое поле или `0` = лимит выключен.
- **Плейсхолдер**: «0 — без лимита»
- **Подсказка (hint) под полем**: «Если процентная комиссия с одного пополнения реферала превышает эту сумму, реферер получит только этот потолок. 0 или пусто — без лимита. Фиксированные бонусы не ограничивает. Действует только в базовой (legacy) схеме наград.»
- **Преобразование**: рубли в поле ↔ копейки в API (`value_kopeks = round(rubles * 100)`). При загрузке: `rubles = kopeks / 100`.
- **Сохранение**: как и остальные настройки раздела — через `PUT /cabinet/admin/settings/REFERRAL_MAX_COMMISSION_KOPEKS` со строковым значением копеек (целое число ≥ 0). Отправлять `0`, а не пустую строку, когда лимит выключен.
- **Валидация**: не отправлять отрицательные значения; дробные копейки округлять до целых (`round`).

### Опционально, если в разделе есть превью/расчёт комиссии

Если рядом уже есть калькулятор или пример расчёта («пополнение X → реферер получит Y»), дополнить его учётом потолка: `выплата = min(округлённая комиссия, потолок)`.

## Требования к мердж-сейф реализации

Как и в предыдущих задачах (см. MARKETING_BOTS_FRONTEND_TASK.md):

- Не переписывать существующие компоненты; добавить поле в существующую форму настроек рефералов минимальным диффом.
- Не переименовывать и не перемещать существующие файлы/экспорты.
- Новая логика — в новых вспомогательных функциях/файлах, подключение — точечными вставками.
- Стиль кода — как в соседних полях той же формы.

## Чек-лист тестирования

1. Раздел «Реферальная программа» в админке открывается, новое поле отображается рядом с процентом комиссии, значение по умолчанию — пусто/0.
2. Ввести 500 и сохранить → перезагрузить страницу → поле показывает 500.
3. В API `GET /cabinet/admin/settings/REFERRAL_MAX_COMMISSION_KOPEKS` значение — `50000`.
4. Оставить 0 и сохранить → значение сохраняется как 0, лимит не действует (в боте комиссия считается как раньше).
5. Отрицательное число невозможно ввести/отправить.
6. Ввод с копейками (например 123.45) → в API уходит `12345`.
7. Ввести дробное 500.5 → сохраняется `50050`, после перезагрузки показывает `500.50`.
8. Пустое поле + сохранить → уходит `0` (лимит выключен), а не пустая строка и не ошибка.
9. При `REFERRAL_REWARD_SCHEME='levels'` подсказка корректна (в UI ничего менять не нужно, но текст подсказки упоминает, что лимит действует только в legacy-схеме).
10. Существующие поля реферальных настроек (процент, бонусы, минимум пополнения) сохраняются и загружаются как раньше — регрессии нет.
11. Права доступа: настройка видна/редактируется только пользователям с правами на настройки (admin/superadmin), как остальные настройки раздела.
12. Проверить, что при сохранении поля другие несохранённые изменения формы не теряются и не отправляются случайно.
